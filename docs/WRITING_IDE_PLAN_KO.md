# 웹소설 집필 IDE 기획서

> 작업명: StoryRail
> 문서 상태: MVP 1차 구현 / 후속 보완 필요
> 최종 수정: 2026-07-10
> 이 문서는 제품 기획서이자 구현 체크리스트다. 완료된 항목만 `[x]`로 변경한다.

## 1. 제품 한 줄 정의

작가가 원고를 직접 쓰는 동안 회차 플롯, 현재 서사 단계, 필수 재료와 복선 상태를 옆에서 계속 보여 주는 로컬 우선 웹소설 집필 IDE.

## 2. 해결하려는 문제

웹소설 작가는 한 문단을 작성하면서도 동시에 다음 정보를 기억해야 한다.

- 이번 회차의 목표와 결말
- 현재 장면이 수행해야 할 역할
- 회차 전체의 긴장과 보상 흐름
- 반드시 넣어야 할 사건, 정보, 복선과 회수
- 고구마, 사이다, 개그, 대화 등 독자 경험을 만드는 재료
- 다음 회차로 넘겨야 할 질문과 인물 상태

기존 문서 편집기는 원고를 쓰는 공간만 제공하고, 별도의 설정 문서와 체크리스트는 집필 흐름을 자주 끊는다. StoryRail은 이 정보를 원고 옆에 배치하고 현재 필요한 항목만 보여 줌으로써 작가의 작업기억 부담을 줄인다.

## 3. 제품 원칙

### 3.1 작가가 작성한다

- 이 제품의 기본 기능은 원고를 생성하거나 대신 작성하지 않는다.
- 가이드는 구체적인 내용이나 문장이 아니라 서사적 기능을 제시한다.
- 향후 AI 기능이 추가되더라도 제안만 하며 원고와 계획을 자동 변경하지 않는다.

### 3.2 구조는 안내하되 강제하지 않는다

- 하나의 구조 단계에는 여러 문단이 포함될 수 있다.
- 문단 입력만으로 구조 단계를 자동 완료하지 않는다.
- 작가는 현재 단계를 완료, 보류, 건너뛰기, 분할 또는 추가할 수 있다.

### 3.3 플롯, 구조, 재료를 분리한다

| 구분 | 답하는 질문 | 예시 |
|---|---|---|
| 플롯 | 이번 화에 무슨 일이 생기는가? | 시험이 조작되었다는 의심이 생긴다 |
| 구조 | 현재 부분은 어떤 역할을 하는가? | 첫 대응이 더 큰 문제를 만든다 |
| 재료 | 이번 화에 무엇을 넣어야 하는가? | 복선 환기, 개그, 작은 사이다 |

세 정보는 연결할 수 있지만 같은 목록에 섞지 않는다.

### 3.4 체크 여부보다 근거를 남긴다

- 체크리스트 항목은 가능하면 해당 원고 문단에 연결한다.
- 연결된 항목을 누르면 원고 위치로 이동한다.
- 복선과 핵심 사건은 `완료됨`뿐 아니라 어디에서 어떻게 사용되었는지 확인할 수 있어야 한다.

### 3.5 로컬 우선으로 동작한다

- 로그인과 서버 연결 없이 집필을 시작할 수 있어야 한다.
- 자동 저장, 백업, 내보내기를 기본 기능으로 제공한다.
- 네트워크 또는 AI 서비스 장애가 집필을 막아서는 안 된다.

## 4. 목표 사용자

### 핵심 사용자

- 회차 단위로 연재하는 웹소설 작가
- 장기 플롯과 복선을 별도 문서로 관리하는 작가
- 원고를 쓰는 동안 구조적 가이드가 필요하지만 AI 대필은 원하지 않는 작가

### 주요 사용 상황

1. 집필 전에 이번 회차의 플롯과 구조 레일을 준비한다.
2. 원고를 쓰며 현재 구조 단계의 지침을 확인한다.
3. 단계를 충족하면 단축키 또는 버튼으로 다음 단계로 이동한다.
4. 사용한 재료와 복선을 원고 문단에 연결하고 체크한다.
5. 회차를 마칠 때 실제 결과와 다음 회차로 넘길 상태를 정리한다.

## 5. 핵심 개념

```text
작품
├─ 아크
│  ├─ 회차
│  │  ├─ 장면
│  │  │  ├─ 구조 단계
│  │  │  └─ 원고 문단
│  │  ├─ 재료 체크리스트
│  │  └─ 회차 결과
│  └─ 아크 목표와 진행 상태
├─ 복선 원장
├─ 인물 및 설정
└─ 구조 프리셋
```

### 구조 단계

집필 순서를 안내하는 최소 단위다. 다음 정보를 가진다.

- 이름: `첫 번째 대응`
- 구조 지침: `문제를 해결하지 말고 대응의 비용을 발생시킨다.`
- 상태: 대기 / 진행 중 / 완료 / 건너뜀
- 연결된 장면과 원고 문단
- 선택적 메모

### 재료

회차 안에 배치해야 하는 요소다.

- 분류: 사건 / 정보 / 복선 / 감정 / 관계 / 개그 / 대화 / 고구마 / 사이다 / 보상 / 사용자 정의
- 중요도: 필수 / 권장 / 선택
- 상태: 미사용 / 사용 / 다음 회차로 이동 / 제외
- 연결된 원고 문단

### 복선

여러 회차에 걸쳐 생명주기를 갖는 특수한 재료다.

- 복선의 실제 의미와 독자가 현재 알 수 있는 의미
- 심기, 환기, 왜곡, 회수 이벤트
- 예정 회차와 실제 배치 문단
- 상태: 계획 / 활성 / 회수 준비 / 회수 / 폐기

## 6. 기본 화면 구조

```text
┌─────────────────┬───────────────────────────┬─────────────────────┐
│ 작품 탐색기      │ 원고 편집기                │ 회차 내비게이터       │
│                 │                           │                     │
│ 아크/회차/장면   │ 작가가 직접 원고 집필       │ 회차 플롯             │
│ 인물/설정/복선   │ 문단별 재료 태그 표시       │ 현재 구조 단계        │
│ 구조 프리셋      │                           │ 재료/복선 체크리스트  │
├─────────────────┴───────────────────────────┴─────────────────────┤
│ 회차 진행 레일 · 저장 상태 · 글자 수 · 집중 모드                 │
└───────────────────────────────────────────────────────────────────┘
```

### 왼쪽: 작품 탐색기

- Scrivener 또는 VS Code처럼 작품의 전체 구조를 트리로 표시한다.
- 아크, 회차, 장면을 생성하고 순서를 변경할 수 있다.
- 인물, 설정, 복선 원장과 구조 프리셋에 접근한다.

### 가운데: 원고 편집기

- 원고 작성에 가장 넓은 공간을 사용한다.
- 문단을 재료 및 복선 항목에 연결할 수 있다.
- 자동 저장 상태와 회차 글자 수를 표시한다.
- 집중 모드에서는 좌우 패널을 접고 현재 지침 한 줄만 남긴다.

### 오른쪽: 회차 내비게이터

다음 탭을 제공한다.

1. `플롯`: 회차 목표, 시작 상태, 종료 상태, 필수 사건
2. `진행`: 구조 단계와 현재 단계의 지침
3. `재료`: 회차 체크리스트와 문단 연결 상태
4. `복선`: 이번 회차에 심기, 환기, 회수할 복선
5. `결과`: 실제 상태 변화와 다음 회차로 넘길 항목

## 7. 핵심 사용자 흐름

### 7.1 회차 준비

1. 새 회차를 만든다.
2. 회차의 한 줄 목표와 시작·종료 상태를 적는다.
3. 구조 프리셋을 선택하거나 직접 단계를 구성한다.
4. 필수 사건, 복선, 재미 요소를 재료 목록에 추가한다.
5. 첫 구조 단계를 활성화하고 집필을 시작한다.

### 7.2 문단 집필과 단계 진행

1. 현재 단계의 이름과 구조 지침을 확인한다.
2. 필요한 만큼 문단을 작성한다.
3. 관련 재료가 사용되었다면 원고 문단과 연결한다.
4. `완료하고 다음`을 실행한다.
5. 다음 구조 단계가 활성화되고 새 지침이 표시된다.

권장 단축키:

| 동작 | 단축키 초안 |
|---|---|
| 현재 단계 완료 후 다음 단계 | `Ctrl+Enter` |
| 선택 문단을 재료에 연결 | `Ctrl+Shift+Enter` |
| 이전/다음 구조 단계 선택 | `Alt+↑` / `Alt+↓` |
| 가이드 패널 열기/닫기 | `Ctrl+J` |
| 빠른 저장 | `Ctrl+S` |

단축키는 사용자 설정으로 변경할 수 있게 설계하되 MVP에서는 고정해도 된다.

### 7.3 회차 마감

1. 미완료 필수 재료와 복선을 보여 준다.
2. 계획한 종료 상태와 실제 결과를 비교한다.
3. 남은 항목을 완료, 다음 회차로 이동 또는 제외 처리한다.
4. 새로 발생한 질문과 인물·설정 변화를 기록한다.
5. 회차를 완료 상태로 변경한다.

필수 항목이 남아 있어도 회차 완료를 막지 않고 경고만 한다.

## 8. 구조 프리셋

### MVP 기본 프리셋

#### 일반 진행형

1. 오프닝 훅
2. 즉각적인 목표 제시
3. 방해 요소 등장
4. 첫 대응
5. 대응의 비용 또는 상황 악화
6. 정보나 가능성 일부 공개
7. 작은 결과 또는 보상
8. 다음 목표 형성
9. 엔딩 훅

#### 고구마·사이다형

1. 부당함 또는 결핍 제시
2. 해결 기대 형성
3. 첫 시도 좌절
4. 압박과 감정 축적
5. 반격 조건 확보
6. 공개적인 반격
7. 인정, 보상 또는 관계 역전
8. 더 큰 갈등의 징후

#### 관계 진전형

1. 현재 관계 거리 제시
2. 공동 목표 또는 강제 접촉
3. 가치관이나 방식 충돌
4. 예상 밖의 면모 발견
5. 취약점 또는 진심 일부 노출
6. 관계를 바꾸는 선택
7. 새로운 거리와 미해결 감정 확정

프리셋의 단계는 회차에 복사된 뒤 자유롭게 수정할 수 있어야 한다. 원본 프리셋 변경이 이미 작성 중인 회차를 자동 변경하지 않는다.

## 9. 기능 요구사항

### FR-01 작품 관리

- 작품을 생성, 이름 변경, 복제, 보관할 수 있다.
- 아크, 회차, 장면을 트리 형태로 관리할 수 있다.
- 드래그 또는 명시적인 이동 명령으로 순서를 바꿀 수 있다.

### FR-02 원고 편집

- 제목, 본문, 문단 구분을 보존한다.
- 실행 취소와 다시 실행을 지원한다.
- 입력 중 자동 저장한다.
- 회차 글자 수를 표시한다.

### FR-03 구조 진행

- 회차마다 구조 단계 목록을 가진다.
- 한 번에 하나의 단계를 현재 단계로 표시한다.
- 완료, 건너뛰기, 되돌리기, 추가, 삭제, 순서 변경을 지원한다.
- 현재 단계의 구조 지침을 편집기 옆 또는 집중 모드 HUD에 표시한다.

### FR-04 재료 체크리스트

- 기본 분류와 사용자 정의 분류를 제공한다.
- 중요도와 상태를 관리한다.
- 하나의 재료를 하나 이상의 원고 문단에 연결할 수 있다.
- 미완료 필수 재료를 회차 마감 시 경고한다.

### FR-05 복선 원장

- 복선별 심기, 환기, 왜곡, 회수 계획을 관리한다.
- 각 이벤트를 회차와 원고 문단에 연결한다.
- 예정 회차가 지났지만 미완료인 이벤트를 표시한다.

### FR-06 회차 결과와 연속성

- 계획한 시작·종료 상태와 실제 결과를 별도로 기록한다.
- 다음 회차로 이동한 재료를 추적한다.
- 미해결 질문과 인물·설정 변화를 다음 회차 준비 화면에서 볼 수 있다.

### FR-07 저장과 이동성

- 브라우저 로컬 저장소에 자동 저장한다.
- 전체 프로젝트를 JSON으로 내보내고 다시 가져올 수 있다.
- 회차 원고를 Markdown 또는 일반 텍스트로 내보낼 수 있다.
- 데이터 형식에 버전 번호를 포함한다.

## 10. 비기능 요구사항

- 일반적인 키 입력에서 편집기 반응이 즉각적이어야 한다.
- 새로고침이나 비정상 종료 후 마지막 자동 저장 상태를 복원해야 한다.
- 패널 너비와 접힘 상태를 기억해야 한다.
- 키보드만으로 구조 단계 진행과 저장을 수행할 수 있어야 한다.
- 색상만으로 완료, 진행, 경고 상태를 구분하지 않는다.
- 모바일은 원고 확인과 간단한 수정까지만 고려하며 MVP의 주 대상은 데스크톱이다.

## 11. 초기 데이터 모델

정확한 타입은 구현 단계에서 확정하되 다음 관계를 유지한다.

```text
Project
  id, title, arcs[], foreshadows[], presets[], settings

Arc
  id, title, goal, episodes[], order

Episode
  id, title, synopsis, startState, targetEndState, actualResult
  scenes[], steps[], ingredients[], unresolvedQuestions[], status

Scene
  id, title, purpose, content, order

GuideStep
  id, title, instruction, status, sceneId?, paragraphRefs[], order

Ingredient
  id, category, title, description, priority, status
  paragraphRefs[], sourceEpisodeId?, movedToEpisodeId?

Foreshadow
  id, title, truth, readerBelief, status, events[]

ForeshadowEvent
  id, type, plannedEpisodeId, actualEpisodeId?, paragraphRefs[], status

ParagraphRef
  sceneId, paragraphId
```

원고 문단 연결을 위해 문단마다 영속적인 ID를 부여해야 한다. 문단의 순서가 바뀌어도 연결이 끊어지지 않아야 한다.

## 12. 기술 방향 초안

MVP는 별도 설치 없이 실행 가능한 데스크톱 중심 웹앱으로 만든다.

- 애플리케이션: React + TypeScript + Vite
- 편집기: Tiptap/ProseMirror 계열 검토
- 상태 관리: 가벼운 전역 상태 저장소
- 로컬 데이터: IndexedDB
- 내보내기: 버전이 포함된 JSON, Markdown, TXT
- 테스트: 핵심 상태 전환 단위 테스트 + 주요 집필 흐름 브라우저 테스트

현재 루트의 `index.html`은 기존 프로젝트 소개 페이지이므로 직접 교체하지 않는다. 새 애플리케이션은 별도 디렉터리에 만들고, 배포 방식이 확정된 뒤 소개 페이지와 연결한다.

## 15. MVP 최종 인수 시나리오

다음 시나리오가 모두 성공하면 MVP를 완료한 것으로 본다.

1. 사용자가 새 작품과 아크, 세 개의 회차를 만든다.
2. 두 번째 회차에 목표와 필수 사건을 입력한다.
3. `일반 진행형` 프리셋을 적용하고 단계 하나를 수정한다.
4. 현재 구조 지침을 보며 여러 문단을 작성한다.
5. `개그`, `목표 제시`, `붉은 반지 환기`, `작은 사이다` 재료를 만든다.
6. 각 재료를 서로 다른 원고 문단에 연결한다.
7. 단축키로 구조 단계를 순서대로 완료한다.
8. 미완료 필수 항목 경고를 확인하고 해당 문단으로 이동한다.
9. 실제 회차 결과와 미해결 질문을 기록하고 회차를 완료한다.
10. 다음 회차에서 이전 결과와 이동된 항목을 확인한다.
11. 브라우저를 다시 열어도 모든 정보가 유지된다.
12. 프로젝트 JSON과 회차 Markdown을 내보낸다.

## 16. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 가이드가 너무 많아 집필을 방해함 | 현재 단계의 지침 한 개만 기본 노출하고 나머지는 접는다 |
| 구조가 작가를 구속함 | 건너뛰기, 분할, 추가와 사용자 프리셋을 제공한다 |
| 체크만 하고 실제 원고에 반영하지 않음 | 체크리스트와 원고 문단의 연결을 핵심 기능으로 둔다 |

| 로컬 데이터 손실 | 자동 저장 상태, JSON 백업, 복구 검증을 제공한다 |
| 기능이 설정 관리 도구로 비대해짐 | MVP의 중심을 원고 편집과 구조 진행에 둔다 |
